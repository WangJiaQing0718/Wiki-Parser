                                            │  MERGE + DEL+INS  │
    The **raw** and **processed** tables use `revision_id` as their primary key and upsert via `MERGE`, so re-runs produce no duplicates there. The three **hierarchical** tables (`simplewiki_sections` / `simplewiki_paragraph` / `simplewiki_sentence`) are delete-then-insert per flush: the rows of the revisions in the batch are deleted and re-inserted in one transaction (delete keyed on `revision_id`), so a re-run replaces each revision's section/paragraph/sentence rows in place and stale detail rows from a previous run (or a changed parse chain) are cleaned up automatically. The **component** tables are likewise delete-then-insert per flush, keyed on `page_id` (each table carries a `page_id BIGINT` column, a `UNIQUE` constraint on `<type>_id`, and a `page_id` index, all in the CREATE TABLE since tables are always created fresh at startup; `id` is a DB IDENTITY; `<type>_id = <type>-<page_id>-<seq>` where `seq` is the 1-based occurrence order on the page, assigned in the worker so the id in `text_process` matches the row): re-running the same dump replaces the component rows in place, and the delete covers every row of the pages being re-inserted, so stale rows from a changed parse chain (fewer components than a previous run) are cleaned up automatically; a duplicate `<type>_id` fails loudly on the UNIQUE constraint. `--max-pages` controls how much is processed.

    XML imports also have logical resume. The `simplewiki_parse_checkpoint` table records each terminal `(source_id, revision_id)` only after both the raw writer and every processed sink commit the same batch. A subsequent XML run reads and decompresses from the beginning, but filters `completed` and `completed_with_errors` revisions before they reach either writer or WTP. A crash before the checkpoint transaction merely repeats idempotent output writes on the next run; it cannot skip unwritten data. Use `--no-resume` for a deliberate full reprocess, or `--retry-errors` to run only terminal rows that previously had parse errors again.
